## 1. The project in one paragraph

Beauty Face Lift is a one-person cosmetic studio (owner: Teresa Stimac, Bahnhofstrasse 94, 8001 Zürich). The agency **mediapaulo** (the user of this repository) builds and runs its website and marketing. The site is an Astro 7 static build (36 pages, German, "Sie") served by a Cloudflare Worker with Static Assets at **https://beautyfacelift-zuerich.ch**. The Worker also runs the APIs: `/api/contact` (enquiry forms → e-mail via Resend) and `/api/track` (Meta Conversions API). Bookings run on Treatwell. The repository is `lefteyep/beautyfacelift` (private); **a push to `master` deploys to production** through GitHub Actions. The old WordPress site `beautyfacelift.ch` still exists and will be shut down (redirect map is already in the Worker).

**Lead-Cockpit rule (2026-10-20):** Teresa must learn nothing about the lead cockpit until it is finished and fully tested. ## 6. How to work in this repository

- **Branches:** `codex/<task>` from `origin/master`, one PR per batch; parallel work in sibling worktrees under `../astro-v2-worktrees/` (see [../../AGENTS.md](../../AGENTS.md)). Remove worktrees after merge.
- **Gates before every PR:** `npm run check` (0 errors), `npm run build`, `npm audit --audit-level=moderate` (0), `npm run qa:carbon-lp && npm run qa:aquafacial-lp && npm run qa:aquafacial-combo-lp && npm run qa:simple-lps && npm run qa:docs && npm run qa:marketing && npm run qa:contact`, `node scripts/seo-plan-smoke.mjs`, `npm run launch:check`, `npx wrangler deploy --dry-run`. The PR branches add `npm run qa:leads` and `npm run harness:*`.
- **Testing without touching production:** the QA scripts assert source contracts; behaviour is proven with harness scripts that import a Worker route with `globalThis.fetch` stubbed (see `scripts/harness/`, e.g. `capi-harness.mts`, `cr3-harness.mts`, `oldsite-harness.mts`, `worker-local-server.mts`) and with Playwright live checks that abort all measurement requests (`scripts/live-tests/`, README there). Never POST to the live `/api/contact` or `/api/track` except for a user-approved labelled test.
- **Docs:** `docs/current/` is the source of truth; `qa:docs` rejects known stale claims; `docs/README.md` indexes the docs; STATUS.md gets a row per release, TODO.md the open work with dates and decisions.
- **Windows notes:** git uses `core.autocrlf=true` — normalise `\r\n` in scripted patches; in Git Bash prefix node commands that take `/path/` arguments with `MSYS_NO_PATHCONV=1`; never use bare `git stash` (shared across worktrees). CI runs Node 22 / npm 10.9 (keep `overrides` top-level; after dependency changes run `npx -y npm@10.9.9 ci --ignore-scripts` in a clean copy). The scratchpad tooling used `playwright-core@1.58.2` with Chromium `chromium-1228`.
- **Dashboards need a human:** Cloudflare (secrets, Zero Trust, Email Routing), Meta Ads Manager/Events Manager, Resend, Treatwell, Search Console, GA4. Write the exact steps for the user instead of assuming access.

## 7. Lessons from October (so they are not learned twice)

- **Test tracking on the live page with ad parameters** and capture `/api/track` status codes; local tests skip CAPI (https-only guard), which is how the broken allow-list went unnoticed for five months.
- Resend's shared test sender only delivers to the account owner; the branded sender needs the verified domain.
- Turnstile fails with 110200 when the hostname is missing in the widget; `/kontakt/` lost every enquiry for a while because of that.
- The Turnstile-exempt ad pages receive bot POSTs; any customer-facing automation must be rate-capped. The review found that #57's original quota checks were not atomic; R1/R8 require repair and verification before enabling mail.
- Google Search Console's manual indexing quota is about 11 requests per day per property.
- The Resend connector in the user's Claude account points at another client's account — never use it to look up this project's mails; the user sees enquiries via BCC.
- `security-smoke.mjs` targets production and skips the Supabase-backed legacy checks; `/admin/` becomes 302/401 with Access (updated in #56).
- Treatwell has no API; "sync" means reading its notification e-mails (plan Phase 2).
